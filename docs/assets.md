# Asset bundles and images

`rust-flutter-assets` compiles a manifest into immutable data embedded in the app's
binary or Android shared library. The same logical keys work on desktop and
Android without a working directory, network connection or storage permission.
New projects generated by the CLI include the manifest, build script and a bundled
welcome text. The gallery adds PNG density variants and an assets page.

Create `assets.json` next to `Cargo.toml`:

```json
{
  "version": 1,
  "assets": [
    "assets/message.txt",
    "assets/badge.png",
    { "path": "assets/android/", "platforms": ["android"] }
  ]
}
```

A path ending in `/` includes direct files in that directory. Other subdirectories
require their own entries. For each logical file, the compiler also discovers
numeric density directories beside it, for example `assets/2.0x/badge.png` and
`assets/3x/badge.png`. The main file is 1×. A manifest entry may omit its main file
when at least one density variant exists. Explicitly list that logical key in this
case. Duplicate density values are errors. Repeated/overlapping manifest entries
are deduplicated. Paths use normalized `/` separators, remain relative to the
manifest's directory and cannot escape it through symlinks. Platform filters use
Rust target OS names, such as `android` and `macos`; excluded files need not exist
on the build machine. Unknown fields, unsupported manifest versions, missing
assets and invalid paths fail the build.

Add the lightweight build dependency (adjust the path to your checkout):

```toml
[build-dependencies]
rust-flutter-assets = { path = "/path/to/rust-flutter/crates/rust-flutter-assets", features = ["build"] }
```

`build.rs`:

```rust
fn main() {
    let output = std::path::PathBuf::from(std::env::var_os("OUT_DIR").unwrap())
        .join("assets.rs");
    rust_flutter_assets::build::compile("assets.json", output)
        .expect("compile application assets");
}
```

The compiler writes a deterministic Rust expression and Cargo rerun directives
for the manifest, asset files, and discovery directories. Adding a density variant
or a file in a declared directory triggers rebundling. The build helper does not
link a windowing system or GPU library into the build process. Cargo compiles it
for the host while embedding the selected target's data. Runtime applications
access the types through `rust_flutter::assets`:

```rust
use rust_flutter::assets::{AssetBundle, AssetImages, EmbeddedBundle};

static ASSETS: EmbeddedBundle = EmbeddedBundle::new(
    include!(concat!(env!("OUT_DIR"), "/assets.rs"))
);

let message = ASSETS.load_string("assets/message.txt")?;
let bytes = ASSETS.load("assets/badge.png")?;
let selected = ASSETS.resolve("assets/badge.png", 2.625)?;
assert_eq!(selected.scale, 3.0); // With the 1×, 2× and 3× variants above.
```

`AssetBundle` is an immutable-source trait. Applications and tests can substitute
another implementation instead of using a global bundle. `load` resolves at 1×;
when no 1× variant exists it uses the density selection rule. `load_string` borrows
UTF-8 text and returns an explicit error for invalid encoding. `resolve` returns
physical path, density and borrowed bytes. Invalid or nonpositive densities and
missing keys return errors.

Image resolution uses the Flutter policy: exact match first; otherwise choose the
next larger variant below 2× density, and the nearest variant at 2× or above. Ties
at higher densities choose the lower variant. Outside the available range use the
nearest endpoint. Images should have physical dimensions proportional to their
scale so their logical size stays constant. [Flutter asset resolution source](https://github.com/flutter/flutter/blob/master/packages/flutter/lib/src/painting/image_resolution.dart).

Own an `AssetImages` cache in your application model, then use it while building:

```rust
let mut images = AssetImages::new(&ASSETS); // Create once, not every frame.
// Inside Application::build:
let image = images.load(ui.ctx(), "assets/badge.png")?;
image.show(ui); // Physical dimensions / variant scale, in logical points.
// Or use image.texture with an egui::Image for custom sizing, tint and UVs.
```

PNG, JPEG and static WebP decoding is enabled. The cache selects for the current
egui pixels-per-point value and retains the decoded texture for later frames.
`load_at_density` permits an explicit ratio. Default limits retain at most 128
textures / 32 MiB of RGBA pixels. `ImageCacheLimits` configures those limits;
zero entries disables retention. LRU eviction releases cache-owned handles.
Caller-held `AssetTexture` clones can keep textures alive after eviction, so the
limit does not bound all GPU or process memory. Decoder scratch and pixel
conversion allocations are separate; decoder allocation limits are best effort.
Image dimensions and RGBA output size are checked before full decode. Textures
must also fit the context's maximum texture dimensions. A different egui context
clears cache ownership rather than reusing texture IDs from another renderer.
`clear` releases retained textures, which is useful on low-memory notifications.

Decoding is synchronous; preload modest assets during initialization and move
large decoding workloads off the UI thread before advertising smooth large-image
loading. This is an embedded-bundle and static-image foundation. SVG, animated
images, image streams, automatic package-asset discovery, network/disk caches,
transformer plugins, native AssetManager/NSBundle lookup, deferred downloads and
font declaration tooling remain incomplete. Files embedded in the Rust library
are not automatically registered as Android AssetManager files. The manifest is
original Rust tooling, not a parser for Flutter's pubspec or binary asset manifest.

Verification includes density/decoding/cache tests, the GPU-free Cargo rebuild
smoke script, the generated application's compilation, desktop rendering outside
the source directory, and a rendered 3× Android image on the test emulator.
Both debug APKs contain all three original PNG byte sequences in their native
library. Broader devices, macOS rendering and image formats outside those enabled
above remain separate gates. See [verification](verification.md).
